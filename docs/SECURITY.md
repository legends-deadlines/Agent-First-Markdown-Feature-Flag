# Модель безопасности и защиты от несанкционированных модификаций

## Назначение

Модель безопасности `mdflag` предназначена для предотвращения случайного или неавторизованного изменения настроек фича-флагов AI-агентами (Cursor, Claude Code, Antigravity), которые действуют в кодовой базе проекта.

## Трёхуровневая защита (3-Layer Protection Model)

```text
[ Слой 1: SHA-256 Хеширование ] ──► Обнаруживает любые изменения текста в файле
            │
[ Слой 2: Разделение MCP-инструментов ] ──► Агент умеет только mdflag_create, но не mdflag_rollout
            │
[ Слой 3: Git pre-commit hook ] ──► Блокирует коммит при несовпадении хешей в mdflag verify
```

### Слой 1: Хеширование секций (SHA-256)
- Каждая секция файла (`AGENT_WRITABLE` и `HUMAN_CONTROLLED`) хешируется отдельно.
- Хеши записываются в блок `INTEGRITY`.
- Изменение хотя бы одного символа вне вызова официального CLI приводит к нерасхождению хешей при проверке.

### Слой 2: Разделение скоупа MCP-инструментов
- **Инструмент агента**: `mdflag_create` — позволяет AI-агенту генерировать новый флаг в статусе `draft`.
- **Инструмент человека**: `mdflag rollout` / `mdflag set-status` — доступен только разработчику в консоли. Агент не имеет инструментального права на изменение статуса раскатки.

### Слой 3: Автоматический верификатор в Git-хуках
- При попытке выполнить `git commit` локальный хук вызывает команду `mdflag verify`.
- Если агент отредактировал `HUMAN_CONTROLLED` напрямую в Markdown-файле, пересчитанный хеш не совпадет с записью в `INTEGRITY`.
- Коммит блокируется до подтверждения человеком.

## Матрица возможностей и ограничений

| Свойство | Обеспечивается? | Механизм |
|---|---|---|
| Обнаружение несанкционированного изменения | Да | SHA-256 хеширование (Слой 1) |
| Защита от случайного редактирования агентом | Да | Инструкции + разграничение MCP (Слой 2) |
| Блокировка невалидных коммитов | Да | Git pre-commit hook (Слой 3) |
| Абсолютная криптографическая защита от зловредного кода | Частично | На уровне локального разработчика достаточно |
