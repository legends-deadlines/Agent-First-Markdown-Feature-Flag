# Дорожная карта разработки (MVP Roadmap)

## Принцип приоритизации

Минимальный замкнутый цикл ценности:
1. Агент создает флаг -> 2. Человек видит флаг -> 3. Код читает флаг -> 4. Человек переключает флаг -> 5. Код реагирует.

## Этапы реализации

### Минимально жизнеспособный продукт (MVP: Этапы 1–4)

| Этап | Задача | Назначение | Статус |
|------|--------|------------|--------|
| **Этап 1** | Формат файла флага + парсер + валидатор хешей | Задание спецификации `.mdflag/*.md` и парсера в `internal/flagstore` | [IN_PROGRESS] |
| **Этап 2** | MCP-инструмент `mdflag_create` | Возможность создания флагов AI-агентом через stdio MCP | [PLANNED] |
| **Этап 3** | Runtime SDK `mdflag.Enabled(name, entityID)` | Вызов проверки флага внутри целевого кода на Go | [PLANNED] |
| **Этап 4** | Бинарное включение (0 или 100%) человеком | Простая смена статуса человека через редактирование/CLI | [PLANNED] |

### Вторая очередь (Этапы 5–6)

| Этап | Задача | Назначение | Статус |
|------|--------|------------|--------|
| **Этап 5** | Постепенный раскат (проценты + детерминированный хеш) | Алгоритм таргетинга по `entityID` в `internal/runtime` | [PLANNED] |
| **Этап 6** | Git-хуки + команда `mdflag verify` | Защита от несанкционированных правок на этапе коммита | [PLANNED] |
