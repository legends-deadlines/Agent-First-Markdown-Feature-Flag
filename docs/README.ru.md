# MDFLAG

**Фича-флаги для AI-агентов. Без SaaS. Без API-ключей. Простые Markdown-файлы в вашем Git-репозитории.**

AI-агенты (Cursor, Claude Code, Copilot, Windsurf) генерируют код и вставляют его прямо в ваш проект. Если код окажется неудачным, всё приложение сломается. Откат изменений в Git требует времени и ресурсов.

Существующие инструменты управления флагами (LaunchDarkly, Statsig, Flipt) недоступны для автономных агентов — они требуют регистрации на веб-сайтах, API-ключей и настройки SDK. У AI-агентов нет браузеров, email и банковских карт.

MDFLAG решает эту проблему, превращая фича-флаги в обычные Markdown-файлы в директории вашего проекта. AI-агенты уже умеют создавать и редактировать файлы — поэтому они сразу могут работать с флагами.

---

## Главная идея

**ИИ умеет создавать файлы в Git, но не может регистрироваться в SaaS.**

Поэтому:
- Традиционные сервисы флагов (LaunchDarkly) = недоступны агентам.
- Флаги на базе Git (MDFLAG) = доступны агентам по умолчанию.

MDFLAG — это первое решение, которое использует существующие возможности ИИ, вместо того чтобы пытаться обучить его внешним регистрациям.

---

## Как это работает

**Без флагов:**
ИИ строит новую комнату, полностью снося старую. Если новая комната выйдет кривой, вы останетесь вообще без жилья.

**С флагами:**
ИИ строит новую комнату рядом со старой. Вы сами решаете, в какой жить. Если с новой что-то не так — вы просто закрываете дверь и остаётесь в старой.

---

## Возможности

- **Agent-native**: Работает через MCP (Model Context Protocol) — без регистрации и API-ключей
- **Git-based**: Флаги хранятся как Markdown-файлы в репозитории и версионируются вместе с кодом
- **Защита целостности**: Проверка SHA-256 хешей предотвращает несанкционированные изменения
- **Постепенная раскатка**: Включение флага для 5% → 25% → 100% пользователей
- **Мгновенный откат**: Изменение одной цифры в файле мгновенно выключает фичу
- **Контроль человеком**: Агенты создают флаги, люди управляют раскаткой

Загрузите последний исполняемый файл для вашей платформы со страницы [Releases](https://github.com/legends-deadlines/Agent-First-Markdown-Feature-Flag/releases):


```bash

cd Agent-First-Markdown-Feature-Flag
go build -o mdflag ./cmd/mdflag/
```

## Быстрый старт

### 1. Создание флага

```bash
mdflag create \
  --name new-checkout-flow \
  --percentage 0 \
  --hypothesis "Повысить конверсию оформления заказа на 5%" \
  --metrics "conversion_rate,checkout_time_seconds" \
  --author "claude-code-agent" \
  --description "Новый одностраничный процесс оформления вместо 3 шагов"
```

Это создаст файл `.mdflag/new-checkout-flow.md`:

```markdown
---
name: new-checkout-flow
percentage: 0
targeting: user_id
status: active
created: 2026-09-17T10:00:00Z
author: claude-code-agent
hypothesis: Повысить конверсию оформления заказа на 5%
metrics:
    - conversion_rate
    - checkout_time_seconds
agent_section_hash: "sha256:a1b2c3..."
human_section_hash: "sha256:d4e5f6..."
---

## Description
Новый одностраничный процесс оформления вместо 3 шагов
```

### 2. Использование флага в коде

```go
import "github.com/legends-deadlines/Agent-First-Markdown-Feature-Flag/pkg/mdflag"

// Инициализируем клиент один раз при старте приложения
client, err := mdflag.New(".mdflag")
if err != nil {
    log.Fatal(err)
}

// Проверяем флаг в обработчике запроса
func handleCheckout(w http.ResponseWriter, r *http.Request) {
    userID := getUserID(r)

    if client.Enabled("new-checkout-flow", userID) {
        // Новый ветка кода
        renderOnePageCheckout(w, r)
    } else {
        // Старая стабильная ветка
        renderThreeStepCheckout(w, r)
    }
}
```

### 3. Постепенная раскатка

```bash
# Включить для 5% пользователей
mdflag rollout --name new-checkout-flow --percentage 5

# Мониторим метрики и увеличиваем до 25%
mdflag rollout --name new-checkout-flow --percentage 25

# Если всё отлично — включаем для всех (100%)
mdflag rollout --name new-checkout-flow --percentage 100

# Если обнаружен баг — мгновенно выключаем (0%)
mdflag rollout --name new-checkout-flow --percentage 0
```

### 4. Проверка целостности

```bash
mdflag verify
```

Пример вывода:
```
[OK]   .mdflag/new-checkout-flow.md

Results: 1 valid, 0 invalid, 1 total
```

## Интеграция с AI-агентами

MDFLAG подключается к AI-агентам через протокол MCP (Model Context Protocol).

### Для Cursor

Добавьте в файл `.cursor/mcp.json` в корне вашего проекта:

```json
{
  "mcpServers": {
    "mdflag": {
      "command": "/path/to/mdflag",
      "args": ["serve", "--dir", ".mdflag"]
    }
  }
}
```

### Для Claude Code

Добавьте в `.claude/mcp.json`:

```json
{
  "mcpServers": {
    "mdflag": {
      "command": "/path/to/mdflag",
      "args": ["serve", "--dir", ".mdflag"]
    }
  }
}
```

### Для Windsurf

Добавьте в `.windsurf/mcp.json`:

```json
{
  "mcpServers": {
    "mdflag": {
      "command": "/path/to/mdflag",
      "args": ["serve", "--dir", ".mdflag"]
    }
  }
}
```

### Инструкция для Агента

Добавьте в системный промпт агента или в `CLAUDE.md` / `.cursorrules`:

```
При внесении экспериментальных изменений в код:
1. Создай фича-флаг с помощью mdflag_create ДО написания кода.
2. Оберни новый код в условие: if client.Enabled("flag-name", entityID) { ... }
3. Установи начальный процент rollout в 0.
4. НЕ редактируй файлы флагов напрямую — используй только инструменты mdflag.
5. Закоммить файл флага и изменения в коде одновременно.
```

## Доступные MCP-инструменты

| Инструмент | Доступ Агента | Описание |
|------------|----------------|----------|
| `mdflag_create` | Да | Создать новый фича-флаг |
| `mdflag_list` | Да | Получить список всех флагов и их статус |
| `mdflag_verify` | Да | Проверить целостность всех флагов |
| `mdflag rollout` | Нет | Изменить процент раскатки (только через CLI) |

Эта модель разграничения гарантирует, что агенты могут создавать флаги, но не могут самостоятельно активировать их или редактировать чужие параметры.

## Модель Безопасности

MDFLAG использует трехуровневую систему защиты:

### Уровень 1: Проверка целостности по хешам

Каждый файл флага содержит SHA-256 хеши отдельных секций:
- `agent_section_hash`: защищает поля, задаваемые агентом при создании.
- `human_section_hash`: защищает поля управления поведением (процент раскатки, статус).

Если кто-то отредактирует файл напрямую без CLI-инструментов, хеши не совпадут, и `mdflag verify` выдаст ошибку.

### Уровень 2: Разграничение прав инструментов

Агенты имеют доступ только к `mdflag_create`, `mdflag_list`, `mdflag_verify`.
У агентов НЕТ доступа к операции `mdflag_rollout` или удалению флагов.
Только человек может изменять процент раскатки через CLI.

### Уровень 3: Git hooks (опционально)

Pre-commit хуки могут блокировать коммиты с нарушенной целостностью флагов. См. [docs/git-hooks.md](git-hooks.md).

## Справка по CLI

### `mdflag create`

Создать новый фича-флаг.

```bash
mdflag create --name <name> --hypothesis <text> [опции]

Опции:
  --name          Имя флага (обязательно, kebab-case)
  --hypothesis    Проверяемая гипотеза (обязательно)
  --percentage    Начальный процент включения 0-100 (по умолчанию: 0)
  --targeting     Таргетинг: user_id, session_id, random (по умолчанию: user_id)
  --author        Имя автора
  --metrics       Метрики через запятую
  --expires       Срок действия в формате RFC3339
  --description   Человекочитаемое описание
  --dir           Директория флагов (по умолчанию: .mdflag)
```

### `mdflag rollout`

Изменить процент раскатки флага.

```bash
mdflag rollout --name <name> --percentage <0-100>

Опции:
  --name          Имя флага (обязательно)
  --percentage    Новый процент 0-100 (обязательно)
  --dir           Директория флагов (по умолчанию: .mdflag)
```

### `mdflag list`

Вывести список всех флагов в директории.

```bash
mdflag list [dir]
```

### `mdflag verify`

Проверить целостность всех файлов флагов.

```bash
mdflag verify [dir]
```

### `mdflag serve`

Запустить MCP-сервер для AI-агентов.

```bash
mdflag serve [--dir <path>]
```

## Библиотека Рантайма

Библиотека Go предоставляет оценку состояния флагов в вашем приложении.

```go
package main

import (
    "log"
    "github.com/legends-deadlines/Agent-First-Markdown-Feature-Flag/pkg/mdflag"
)

func main() {
    // Инициализация при старте
    client, err := mdflag.New(".mdflag")
    if err != nil {
        log.Fatal(err)
    }

    // Опционально: горячая перезагрузка при изменении файлов
    stop, err := client.StartWatcher()
    if err == nil {
        defer stop()
    }

    // Использование в обработчиках
    userID := "user_12345"
    if client.Enabled("new-checkout-flow", userID) {
        // Новый код
    } else {
        // Старый код
    }
}
```

### Детерминированный Таргетинг

Один и тот же ID сущности всегда получает одинаковый результат для конкретного флага:
- Пользователи не видят скачков интерфейса между запросами
- A/B тесты получают стабильные группы
- Отладка становится полностью воспроизводимой

### Вычисление Процента

Для флагов с процентом от 1 до 99 MDFLAG использует хеширование FNV-1a:

```
bucket = FNV-1a(flagName + ":" + entityID) % 100
enabled = bucket < percentage
```

Это обеспечивает равномерное распределение по всем пользователям.

## Жизненный Цикл Флага

1. **Создание** (percentage: 0) — Агент создаёт флаг и обёртывает новый код.
2. **Ревью** — Человек проверяет PR, включая файл флага.
3. **Постепенный rollout** — Человек увеличивает процент: 5% → 25% → 100%.
4. **Мониторинг** — Отслеживание заданных в флаге метрик.
5. **Очистка** — Одно из двух:
   - Удаление флага и сохранение нового кода (при успехе)
   - Установка процента в 0% и откат кода (при неудаче)

## Сравнение с Альтернативами

| Инструмент | Как работает | Проблема для AI-агентов |
|------------|--------------|-------------------------|
| LaunchDarkly / Statsig | SaaS-сервис, требует API-ключи | Агент не может зарегистрировать аккаунт |
| Flipt v2 | GitOps, но требует локальный сервер | Агент не может запустить сервер |
| dif.sh | Markdown-флаги | Нет защиты от модификации агентом |
| **MDFLAG** | Markdown-флаги + защита целостности | **Работает полностью автономно** |

Главное отличие: MDFLAG не только позволяет агентам создавать флаги, но и **защищает их от несанкционированных изменений** — агенты не могут сами включить свой флаг или подделать хеши.

---

## Философия

**Не пытайтесь сделать ИИ идеальным.** ИИ всё равно иногда будет писать код с ошибками.

**Вместо этого:** создайте систему, при которой плохой код ИИ не ломает проект. Изолируйте код ИИ, включайте постепенно, откатывайте мгновенно.

Это не про «замену людей», а про «предоставление людям полного контроля над скоростью ИИ».
